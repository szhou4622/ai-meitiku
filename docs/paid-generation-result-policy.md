# 计费生成的结果保全规则

适用于提示词反推、精修、替换生成、分类草案及其他计费生成链路。

1. 模型实际返回的正文先独立保存，再进行结构解析、质量复核、格式化和索引更新。没有返回内容时不得伪造结果。
2. 区分完整结果、部分结果和完全未生成。单个分镜、单批次或后续复核失败，不得清空其他已完成内容；部分结果须列出问题，不能冒充检查通过。
3. 部分结果可查看、复制、编辑；未经用户采用，不覆盖原稿。重启后仍可找回。原始文本可在设置 → 存储管理 → 已生成内容查看。
4. 自动兼容重试仅限明确拒绝且未生成正文的协议兼容情况。已有正文后不因质量不合格自动重新生成。补生成须由用户主动发起；积分模式仍走现有报价确认，不承诺免费、不篡改扣费结果。
5. 视频反推补生成只合并被标记的问题分镜；已通过的分镜保持原值。已完成画面分析批次不重复发送；仍需抽帧时只发生本地处理。
6. 结算待核对不得显示为免费或已确认扣费。保留原任务标识及精确积分回执；本地结果保全不等于服务端退款或补偿策略。
7. 已下载的媒体文件与元数据索引分离：后续索引保存失败不得删除成品。声音试听以任务日志和成品旁的恢复记录保留下载结果；重放同一任务不再次调用供应商。
8. 真正的程序、存储、账务不确定异常仍须保留诊断；质量不完整显示待核对提示，不能把业务内容不完整一律升级为全局失败弹窗。

9. 报价过期须先核对原任务状态。仅服务端确认仍未提交时，提供“重新报价并继续”；价格变化重新确认。已受理、预占失败待核对、执行中或结算中的任务沿用原编号，不能借续报价重复调用。已完成步骤和积分回执保留；用户暂不执行时，未提交的旧报价记为零扣费。

## 验收门槛

- 故障注入：中间项缺失、截断、连接中断、复核失败、成品生成后索引失败。
- 检查已有内容可见、可取回、可采用，进程重建后内容仍在；检查用户原稿未被覆盖。
- 检查补生成只针对问题项，检查实际调用次数，不以结果文案替代调用计数。
- 回归业务提示和真实异常反例，避免为了保留结果而吞掉授权或存储异常。
- 每次发布须区分源码、预览、安装包与目标设备验证；模拟供应商测试不能宣称真实付费模型或所有作品下载均正常。安装包验收另需真实下载凭据。
