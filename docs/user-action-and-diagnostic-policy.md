# 操作提示与异常诊断的验收规则

正常业务条件使用操作提示：积分不足、授权或登录需验证、缺少配置或输入、文件格式或数量不符合要求、报价过期、内容已变化、已有任务运行、任务仍在处理。提示应说明下一步，并在有对应设置时提供入口。

取消操作不属于异常。取消文件选择、导出或同步，应明确返回 `cancelled: true` 或 `canceled: true`；不得仅返回含义不明的 `ok: false`。取消未必意味着任务未提交或没有扣费，不得擅自做费用承诺。

模型正文不完整、输出截断、缺少分镜字段、拒绝生成、内容限制、响应超时以及外部 AI 服务暂不可用，使用普通状态提示，不弹开发者错误详情。已有内容保留在结果区，说明可补充或自行决定是否重试，不要求用户复制诊断信息；也不因超时承诺未扣费。

只有需要开发者排查的真实异常使用诊断弹窗，包括程序异常、存储或数据损坏、软件内部协议错误、取消时保存失败和无法确认的账务异常。模型生成正文不符合格式不等于软件内部协议错误；不能因为某个任务未完成就一律弹诊断。保留脱敏日志与关联编号。

所有诊断入口共用 `electron/user-action-errors.mjs`：

- 主进程 `diagnosticHandler` 在记录或传出结果前分类。
- 预加载层负责转发，不以“已取消”等模糊前缀吞掉异常。
- 界面 `errorDetails` 与 `ErrorDetailDialog` 再次分类；普通提示不带远程方法名、错误码或诊断编号。
- 新版真实异常携带统一标记，保证 Electron 丢失 Error 属性后仍保持异常分类；不得因异常描述中碰巧含有“积分不足”等文字而改成普通提示。
- 对旧版消息保留兼容解析；文本匹配需限定已知业务提示，不能用宽泛关键词隐藏未知故障。

新增功能、错误码或失败返回结构时，必须检查该状态属于正常业务条件还是实际异常，并更新统一规则及回归用例。

验收至少包含：主进程抛出异常和返回失败对象两条路径、真实生产 `electron/preload.cjs`、业务引导按钮、取消结果、旧格式消息，以及仍应出现诊断框的反例。隐藏 Electron 窗口验证，不抢占用户前台，不触发真实扣费。
