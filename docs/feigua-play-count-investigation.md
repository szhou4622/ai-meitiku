# 飞瓜播放数字段核验（2026-10-07）

任务分支 `codex/feigua-play-count` 从 `origin/main` 的 `4782f66` 建立。实测使用已有开发客户端的已登录飞瓜窗口；此分支交付独立诊断工具及测试，未接入生产结果存储。文档只记录接口结构与匿名核验结论，不保存账号、视频标识、商品标识、签名链接或逐条采集数据。

## 实测结果

截图对应的一组近 7 天、销售额降序 Top5，其列表接口 `/api/v1/aweme/search/listwith` 返回成功，5 条的 `PlayCount` 都是 `--`。逐条打开页面实际提供的详情链接，监听该页正常发出的请求和响应，并通过页面现有 API 客户端复核：

| 来源 | 实测字段 | 结论 |
| --- | --- | --- |
| `/api/v3/aweme/detail/detail/mainPart` | `PlayCount=0`，`PlayCountStr=null` | 不能把这个占位 0 当作实际播放数 |
| `/api/v3/aweme/detail/detail/sumData` | `PlayCountStr=null` | 没有可用的汇总播放数 |
| `/api/v3/aweme/detail/detail/trends` | 通用互动趋势的播放字段为 0 | 不能补齐总播放数 |
| `/api/v3/aweme/detail/detail/awemePromotionTrend` | 日序列含 `DateCode`、`PlayCount`、`IncPlayCount` | 原组 4 条最新点为正；另 1 条最新点归零且增量为负，不能采用 |

带货趋势接口的实际 GET 参数为 `promotionId`、`awemeId`、`dateCode` 和缓存参数 `_`。页面调用方是商品的“视频销售趋势”，图表展示销售额、销量与 GPM，未展示播放量。页面也说明数据来自飞瓜的估算。因此，此接口确实提供候选 `PlayCount`，但还没有证据证明指定商品趋势里的数值就是整条视频的总播放量。

结论：**能取到商品趋势中的候选播放量，尚不能可靠补齐原需求的“视频播放数”。** 不能用该值直接覆盖 `row.plays`，也不能根据 GPM 或销售额自行反推播放量。保持原界面的缺失标记。

## 可重复的诊断工具

先在已有开发客户端中打开需要核验的视频详情，并保持登录。使用当前进程实际开启的本机 CDP 端口和已核验来源的 origin：

```powershell
node scripts/probe-feigua-video-plays.mjs --help
node scripts/probe-feigua-video-plays.mjs --port <本机CDP端口> --origin <已核验来源origin> --cutoff 2026-10-07
```

工具只重放当前详情已经发出的 `mainPart`、`sumData` 与商品趋势 GET 请求；查询参数留在页面进程内，结果仅导出允许的计数和日期。origin、详情视频标识、发布日期、返回身份和请求上下文必须一致；响应期间切换详情会终止核验。403、缺少实际请求、未知客户端、示例数据、最新点归零/回撤、无效日期和未来日期不能生成候选结果。候选结果明确保留 `scope=promotion-trend`、`asOfDate` 与 `verifiedAsVideoTotal=false`。

初次手工打开详情后返回列表时发现，来源页面会重新载入默认筛选条件。最终工具只读取已经打开的详情，不自动切换路由，不修改采集配置、历史结果或生产存储。
