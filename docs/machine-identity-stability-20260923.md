# 机器码读取与历史授权兼容修改（2026-09-23）

## 范围与依据

修改 AI媒体库 1.1.8 工作源码，采用用户分享的千川 0.1.33 对话记录所描述的机制：系统 UUID、PowerShell 完整路径、8 秒单次查询、间隔 500 毫秒重试一次、持久身份、读取失败时保留已有身份。分享来源：https://chatgpt.com/s/cx_6ab38544343481919a28bc315bbc3b12 。本机千川源码为 0.1.18，没有将它误当作另一台电脑的 0.1.33 完整源码。

仅修改媒体库源码和测试；没有访问线上授权接口、修改客户凭证、变更服务端配置、打包或发布。原工作区的时间码兑换反馈修改保持原样。

## 新安装

- Windows 使用系统目录中的 WindowsPowerShell/v1.0/powershell.exe，仅查询 Win32_ComputerSystemProduct.UUID；不串行捆绑 BIOS、主板等查询。
- PowerShell 禁用 Profile，非交互执行。32 位进程运行于 64 位 Windows 时使用 Sysnative；普通进程使用 System32。
- 单次命令超时 8 秒，失败、空值或无效值后等待 500 毫秒再试一次。总命令预算约 16.5 秒。分类记录超时、命令不存在、权限不足、空结果和无效标识，不保存原始错误输出。
- UUID 标准化并过滤全零、全 F、重复值以及已知 SMBIOS 占位值。
- 新 Windows 码保持服务端兼容的 `v2_<64 hex>` 格式，来源为 `windows_system_uuid\0<标准化 UUID>`，仍使用原应用名及原 v2 哈希域。
- macOS 继续使用 IOPlatformUUID；Linux 继续使用 machine-id。macOS/Linux 保留原哈希公式，并增加读取检查和重试。
- 不新增随机种子，不回退到 MachineGuid、MAC、计算机名或拼接残余字段。
- 无有效标识时停止本次生成，允许后续重试；完整身份和兼容缓存保存成功之前，不发起新激活。
- 新身份在原加密记录中增加 `identity_scheme: system_uuid_v1`，不更换应用名、用户数据目录、safeStorage 服务或文件名。
- 新身份检测到 UUID 与保存的摘要冲突时，保留原码和凭证，阻止在线验证、激活、离线授权、刷新会话和解绑。临时读不到 UUID 时沿用已有缓存；已经发现的冲突不会因后续读不到而消失。

## 旧用户兼容

| 现有数据 | 行为 |
| --- | --- |
| 完整旧 v3 身份记录（其中 active 码仍为 v2） | 保留 active 码及原算法来源；Windows 仍用 MachineGuid 检查旧摘要，不用新 UUID 比较旧摘要 |
| 只有旧 v2 裸机器码缓存 | 原码原样迁入身份记录；兼容历史原始大小写和标准化计算结果 |
| 旧随机种子/随机身份 | 恢复并保留旧码，不创建新种子、不转换 UUID 码 |
| 本地码缓存丢失，但凭证有 v2 boundMachineCode | 直接恢复这个精确绑定码 |
| 本地码缓存丢失，仅有完整旧设备凭证 | 用原 session 和 device credential 查询 `/device/status`，仅接受成功响应中的有效 v2 绑定码；不调用 `/activate` |
| 已有 v3 正式绑定 | 保留本地旧 v2 码、v3 正式绑定及原因子绑定；继续现有服务端和离线协议 |
| 无法恢复旧码、凭证解密失败或记录损坏 | 保留数据并明确报错，不猜测旧算法、不自动清除或重新激活 |
| 历史身份存在，但读取硬件或刷新缓存失败 | 原码继续可用；原授权仍需通过既有在线或离线验证 |

旧身份已存在的硬件冲突继续走原有服务端凭证/v3 核验路径；没有批量重算老用户机器码，也没有自动合并或拆分线上绑定。

## 写入与并发

沿用主程序和诊断工具的同一 Electron 单实例锁、进程内共享 Promise、safeStorage 文件写入队列及临时文件原子替换。新身份先提交含算法来源和摘要的完整记录，再写旧格式兼容缓存。完整记录失败时不留下裸缓存；兼容缓存写入失败时，已落盘的完整记录仍保存新算法标记，重启不会误降级为旧身份。

## 验证

命令（只运行隔离测试，不调用线上接口）：

```sh
node --test tests/system-id.test.mjs tests/machine-code*.test.mjs tests/machine-identity*.test.mjs tests/license-*.test.mjs tests/device-diagnostic*.test.mjs
```

测试涵盖 UUID 重试和无效值、同 MachineGuid 不同 UUID、50 次启动读取失败、旧码与旧随机身份、v3 正式绑定、真实临时文件升级、原凭证恢复旧码、写入中断、异机复制、在线/离线授权及现有本地 HTTP 客户端服务端联调。临时文件测试使用测试专用加密接口替身，不接触真实 Keychain/DPAPI。

本次所选回归结果：208 项通过，0 失败，0 跳过，约 5.1 秒。修改的机器码、授权及新增测试模块 ESLint 检查通过；主入口与核心模块语法检查、`git diff --check` 通过。测试期间未启动生产应用。

macOS 本机真实 ioreg 读取成功（一次读取，未输出原始 UUID）；Windows 的 PowerShell、权限和 DPAPI 仍需 Windows 实机验证。未声称在 Mac 模拟测试中完成 Windows 实测。

## 边界

该修改减少由克隆 MachineGuid、读取失败后替代生成、缓存不稳定带来的问题，不能保证硬件厂商或虚拟机提供的 UUID 永远唯一。若两台电脑连 UUID 都相同，仍需现有多因子及服务端冲突核验。已有线上重码为了保护现有授权不会被此次客户端升级自动改掉，需要按具体绑定和硬件证据处理。没有问题电脑实测数据，不能认定历史重码必然来自随机兜底。
