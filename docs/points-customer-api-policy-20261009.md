# 按任务 API 来源区分的积分规则

五个目标板块（分类方案、素材分类工作台、一键去字幕、声音克隆、提示词库）按每个任务实际使用的 API 来源区分扣费：使用用户自己填写的 API，消耗用户在供应商的余额/额度，不扣软件积分；使用平台内置 API，平台承担供应商费用，才允许按费用结算软件积分。

`electron/points-policy.mjs` 记录 `per_task` 双模式。默认优先使用已配置的用户 API；用户 API 报错不能静默切换到会扣软件积分的内置 API。显式选择用户 API 但未配置时，应提示配置；显式选择内置 API 时，应在发起任务前展示积分预算并取得用户确认。

目前内置 API 尚未接通，`platformApiAvailable=false`。没有用户 API 的任务暂不可执行，不冻结、不扣积分。规则解析和准入检查是后续任务接入使用的公共模块，当前业务流程没有中央账本扣费入口，不代表实际兑换或计费已经接通。

预留规则：充值 1 元对应 100 积分；由平台承担 API 成本时，扣分为可核对的实际成本（人民币）× 200；保留 6 位小数积分。服务端应使用整数最小单位或 Decimal，避免浮点与每次向上取整。客户端预留值不作为服务端扣费依据。

基础版、VIP 的时间权益独立于积分余额，共用同一个服务器账户钱包；续期、升级、换绑不重置积分。积分充值与消费开关分开，账户有积分不意味着用户自接 API 的任务就要扣分。

当前真实积分码兑换、中央余额和账单尚未接通，不显示虚构余额或兑换成功。该项范围待用户选择后继续实施。当前不调用服务器扣费端点，不在客户端存放中央账本内部凭证。未来实际结算时，服务器必须同时核对任务的 API 来源、功能收费开关、费用凭据和幂等编号；客户端公共检查不构成扣款授权。平台内置 API 尚未可用时，即使存在积分余额，也不能通过扣积分伪装生成成功。供应商可能对用户重新生成和新的请求再次计费。
