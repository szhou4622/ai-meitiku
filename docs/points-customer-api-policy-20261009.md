最终产品以服务器平台 API 和中央积分结算为主，用户自接 API 是完整积分功能上线前的过渡安排，不作为最终产品的必要条件。

五个目标板块（分类方案、素材分类工作台、一键去字幕、声音克隆、提示词库）按每个任务实际使用的 API 来源区分扣费：使用用户自己填写的 API，消耗用户在供应商的余额/额度，不扣软件积分；使用平台内置 API，平台承担供应商费用，才允许按费用结算软件积分。

火山、中转、MiniMax、阿里云分别保存“使用自己的 API”开关；已有用户默认开启。开启时只调用个人 API，缺少 Key 或调用失败就停止；关闭时只选择平台积分服务，保留已存密钥。两种方式都不能静默切换。任务开始时固定使用方式，重试沿用原方式。

积分模式在发起任务前显示该次任务的所需积分，用户选择运行或取消。不设置固定的单次积分上限，也不让用户填写预算。按 token 或其他可变用量计费时明确显示“预计积分”，完成后按供应商实际用量和核对过的服务价格结算。报价本身不预留、不扣分；确认运行才提交任务。预留金额来自此次服务器报价，不是用户输入的预算。客户端不得发送自定义金额或扣分上限。

平台功能是否开放以服务器鉴权后的 capabilities 为准，同时检查生成开关、消费开关、供应商配置和 `enabled_features`。旧的公共策略模块 `platformApiAvailable=false` 仍用于未接通的业务路径；提示词文本已绑定专用任务网关，不能用这个旧常量判断全部积分功能。未开放的任务不得冻结、扣分或静默切换到个人 API。

计费规则：充值 1 元对应 100 积分；平台任务扣分为核对后的人民币计费金额 × 200，保留 6 位小数积分。供应商实际扣款大于 0 时，以该任务可核对的实际扣款为准；确认实际扣款为 0 时，使用供应商账单中的额度抵扣前计费金额，没有此字段则按标准服务单价 × 实际用量计算。免费额度不会使有计费用量的用户任务免费。正常计价中的缓存命中使用对应缓存单价。

任务记录区分标准价计费金额、额度抵扣前金额与供应商实际扣款。供应商实际扣款没有可核对账单时记为未知，不推断为 0，保留结果和积分预留并标记待核对。仅服务端可信、对应原任务的账单补录能够进入结算，不重新生成，也不接受客户端自报金额。超出用户已确认报价的金额进入核对状态，不静默多扣或截断账单金额。服务端使用整数最小单位或 Decimal，避免浮点与每次向上取整。客户端预留值不作为服务端扣费依据。

火山 Seed 2.1 Lite 文本任务的账单核对已部署：按 API Key 资源 ID、模型版本、小时和应用任务回执核对 token 与调用次数，再核对费用。分账账单不可用时，只有整个账号该模型/小时的用量与该 Key 的应用任务完全一致，才允许使用账号明细账单；其他 Key、模型版本、缺失或部分数据均保留待核对。账单读取凭证单独加密保存在服务器，不进入客户端。客户端持久保存待核对任务编号并后台查询；查询只能结算已有回执，不能再次执行供应商生成。

基础版、VIP 的时间权益独立于积分余额，共用同一个服务器账户钱包；续期、升级、换绑不重置积分。积分充值与消费开关分开，账户有积分不意味着用户自接 API 的任务就要扣分。

服务器积分码兑换、中央余额与流水接口已上线，客户端源码的兑换、余额和账单已接入，只显示经校验的服务器响应。源码预览允许真实设备凭证查询，以及本次用户明确授权的积分生成测试，不提交真实积分码；正式模式可兑换积分码。提示词文本经原设备凭证、服务器报价、用户确认、私有供应商调用和费用核对后进入中央结算。客户端不存放供应商平台密钥或中央账本内部凭证。未开放的平台任务不能通过扣积分伪装生成成功。供应商可能对新的请求再次计费。
