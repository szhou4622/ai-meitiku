## 规则与精度

- 充值：1元=100积分。
- 消费：可核对的供应商实际人民币费用×200积分。
- 中央库使用整数最小单位，1积分=1,000,000单位，响应提供整数单位与6位小数积分文本。
- 费用必须以十进制字符串提供，最多8位小数；拒绝 JSON float、NaN、负数和科学计数法。该精度可无损换算为上述积分单位。
- 仅分类方案、分类工作台、去字幕、声音克隆、提示词库允许平台承担费用的消费；用户自接API拒绝软件积分消费。
- 当前线上消费开关关闭。没有平台任务执行链路和可靠费用证据之前，不启用扣费。

产品经营报告只读参考：其 `por_precise_credits.py` 使用整数单位、Decimal换算、逻辑任务/尝试/模型/费用凭据核对。该实现当前会将换算结果四舍五入到整数积分；媒体库保留6位小数，不照搬其取整策略或旧账户镜像更新方式。

## 用户接口

全部为 POST，路径前缀 `/api/license/ai-media-library/points/`。须携带 `Authorization: Bearer <设备会话>` 和 `X-Device-Credential`，且 JSON 含 `app_name`。响应包含 `ok`、`app_name`、`balance_units`、`reserved_units`、`available_units`、对应小数文本和 `unit_scale`。

| 后缀 | 额外JSON字段 | 用途 |
|---|---|---|
| balance | 无 | 余额、冻结与可用积分 |
| transactions | 可选limit、before_sequence | 限定账户的游标分页流水 |
| redeem | request_id、code | 积分码兑换，同码/同请求重试不会重复入账 |

余额与充值允许已过期但仍有效绑定的媒体库设备凭证；平台新任务仍要求有效时间权益。基础/VIP续期和换绑不重置钱包，钱包以服务器验证的主授权 code_id 定位，不以机器码或当月时间码新建账户。主授权补发导致 code_id 更换时，需后续独立、经认证的账户迁移流程；本批不自动猜测归属。

## 服务器内部接口

仅本机可访问，路径在上述前缀追加 `internal/`，还需服务器私密令牌 `X-AIML-Settlement-Token`。该令牌不发送给客户端、不写代码或日志。

| 后缀 | 必需字段（除app_name） | 说明 |
|---|---|---|
| issue-code | request_id、code、paid_cny | 管理端确认支付后发码；仅保存积分码哈希 |
| reserve | request_id、feature、api_source、budget_cny及设备凭证 | 仅platform_api；冻结预算、生成任务ID |
| commit | task_id、cost_cny、provider、bill_ref、attempt_id、billed_model | 按实际费用扣分，释放多余冻结额度 |
| release | 与commit相同，且cost_cny必须为0 | 有证据确认零费用后释放冻结额度 |

预算由可信服务器任务层提交，不能直接转发客户端金额。费用凭据同样由可信供应商执行/计费层提供，客户端不能提交结算费用。内部提交是可信结算边界，本批尚未实现供应商账单自动查询，不声称仅凭 bill_ref 文本就能证明实际扣款。

任务唯一性按应用、账户、请求编号约束；任务重试必须保持预算/功能参数一致。结算同时核对金额、供应商、费用凭据、调用尝试、模型，不一致返回409。费用凭据不能重复用于另一任务。消费和余额写入在同一 SQLite `BEGIN IMMEDIATE` 事务内完成。

任务失败但供应商收费时走commit，不能自动全额退款；费用不确定时保留冻结等待核对，不按超时直接释放。实际费用超过预算时保留冻结、拒绝超额扣分，执行层应在调用前限制预算并处理人工核对。解绑/换绑过程中已产生的供应商费用可由可信内部任务按原账户完成结算，不允许旧设备继续提交新任务。
