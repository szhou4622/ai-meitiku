# 错误详情与诊断日志（2026-10-07）

设置 → 存储管理增加“日志”占用统计、打开目录和保留规则。顶部右侧上下放置同宽的“重新统计”“导出日志”，窄窗口改为并排，按钮保留在卡片内。

默认保留 14 天、上限 100 MB。可选保留 7/14/30/90 天及 50/100/200/500 MB；达到时间或容量后删除最旧日志。日志位于 userData/diagnostic-logs，以 JSONL 按日期和约 2 MB 文件轮转。

## 记录范围

- 启动、正常退出、环境版本、操作系统及架构。
- IPC 操作开始、结束、参数、结果、耗时、操作诊断编号；异常保留名称、错误码、堆栈和嵌套 cause。
- 返回失败状态的接口也记录失败并展示详情，保持原有返回合同。
- 下载、打标、更新、授权及其他已连接界面的状态/进度事件。
- 主进程控制台、前端控制台、前端未处理异常和 Promise 拒绝。
- 主进程、渲染进程、子进程崩溃；资源加载失败。
- 本地 HTTP 请求方法、路径、状态码、耗时、中断和路由异常；不记录 HTTP 请求体或凭证头。
- 主进程启动的工具进程 stdout/stderr、退出码；下载后端额外完整保存每个输出块，避免只保留错误末尾。

密钥、Cookie、授权头、Token、密码和激活码脱敏；URL 查询参数去除。授权相关接口的凭证参数不记录，展示激活码的返回值不记录。完整指完整保留已记录的诊断过程与错误链，不收集原始媒体二进制、凭证或 HTTP 请求体。日志只能记录启用之后的过程；此前已经被业务代码丢弃的原因无法还原。

## 导出

导出 .json.gz 压缩文件，包含格式版本、导出时间、环境、保留规则、日志文件和授权诊断快照。JSON 可在解压后由开发者直接检查。日志写入故障会显示在日志规则说明中。以流式方式压缩和写盘，避免将整个日志上限一次性装入内存；打开的快照文件句柄保证导出期间自动清理不会丢失已选日志。

错误详情弹窗保留到用户关闭，可复制；异常提示包括具体原因、操作入口、可取得的错误码和诊断编号。编号可关联操作开始及原始错误堆栈。
